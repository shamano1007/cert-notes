原本を更新したので、HTML を再生成してください。

追加の指示: $ARGUMENTS

## 手順

1. **対象の確認** — `doc/` 配下のどの md が変更されたかを確認する（`git status` / `git diff`）。
   引数で特定の教材が指定されていればそれを対象にする。

2. **内容チェック** — 今回の差分に事実誤認・記述の不整合・書式崩れがないか確認する。
   問題があれば指摘し、修正してよいか判断を仰ぐ（軽微な誤字は直してよい）。

3. **書式チェック** — `CLAUDE.md` の「Markdown の書式ルール」に反する記述がないか確認する。
   特に**表（`|` 記法）・コードブロック・番号リスト・ネストした箇条書き・`####` は未対応**なので、
   追加されていたら知らせること。あわせて「過去にやったミス」のチェックコマンドも走らせる。

4. **ビルド** — プロジェクト直下で `python3 build.py`

5. **検算** — 生成物が Markdown と一致しているか数える（`CLAUDE.md` の検算セクション参照）。
   未変換の記法が残っていないかも確認する（生成物に `**` や `<p>- ` が出ていないこと）。

6. **表示確認** — `CLAUDE.md` の「表示確認の方法」に従い、PC とスマホ幅（iframe で 375px）の
   スクリーンショットを撮って崩れがないか目視する。教材を追加した場合は `docs/index.html` も確認する。

7. **報告** — 変更点、用語数・章数、確認結果を簡潔にまとめる。
   数が合わない・変換漏れがある場合は、取り繕わずそのまま報告すること。

## やらないこと

- `docs/` 配下を直接編集しない（自動生成物なので次回ビルドで消える）
- 左メニューの自動スクロール（`scrollIntoView`）を復活させない（理由は `CLAUDE.md` 参照）
- 外部リソース（CDN の CSS / JS / フォント）への参照を足さない
